# Markdown (documents and two evidence files)

## What it is

Markdown is a way to write formatted text in a plain text file. A line starting with `#` is a heading, `- ` starts a bullet, `|`
draws a table, and backticks mark code. GitHub and most editors show it formatted; as plain text it is still easy to read.

## Why this repository uses it

The repository explains itself in documents next to the code (README with the "Done when" proof table, ARCHITECTURE, CHANGELOG,
four decision records). Two evidence files are Markdown as well: the pack's index, which an auditor reads first, and the
access-review record.

## Where it appears

| File | What it does with this technology |
| --- | --- |
| `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` | The documents. |
| `docs/adr/0001` to `0004` | Decision records. |
| `evidence/INDEX.md` | Generated: one line per evidence file with its date and what it proves. |
| `evidence/C6-access-review.md` | The access review with a before and after. |
| `build/report.md` | Generated by `make report`. |
| `tech/*.md` | These notes. |

## How it works underneath

Markdown is not a program; a viewer turns it into HTML for display. The generated files are written by Python as plain text with
Markdown markers, so they are readable in a terminal as well.

## Walkthrough of this repository's use

`evidence/INDEX.md`:

```markdown
# Evidence pack index

Pack date: 2026-10-27T01:37:07Z. Each file below was produced by a command in this repository (`make evidence`); `manifest.json` records its hash, so a hand edit fails `make verify`.

| File | Control | Proves | Run by | Date | Period | Refreshed |
| --- | --- | --- | --- | --- | --- | --- |
| C1-access-list.txt | C1 Access control | who can do what today, in each system | ada | 2026-10-27 | point in time | weekly |
| C2-changes.csv | C2 Change management | reviewed, traceable changes, from approval to deployment | ada | 2026-10-27 | sample of recent merges | weekly |
| C3-log-sample.txt | C3 Logging and monitoring | who did what and when, without note content | ada | 2026-10-27 | sample | weekly |
| C3-alert-test.txt | C3 Logging and monitoring | the alert fires on a test event, with its timestamp beside the action | ada | 2026-10-27 | point in time | monthly |
| C4-restore-test.txt | C4 Backup and recovery | a real restore into a scratch database, verified by row count, with its duration | ada | 2026-10-27 | point in time | monthly |
| C5-scan-report.json | C5 Vulnerability management | the dependency scan of a build, with its run id and the blocking rule | ada | 2026-10-27 | every build | every build |
| C6-access-review.md | C6 Access review | a reviewer decided every access; the removed access is gone on a re-run | ada | 2026-10-27 | quarterly point in time | quarterly |
```

The index is generated (`make evidence` writes it last). The `|` characters make a table; the verifier checks that every evidence
file appears in it and that the index itself is recorded in the manifest.

`docs/adr/0002-the-audit-log-is-append-only-in-the-database.md`:

```markdown
# 2. The audit log is append-only in the database

Status: accepted, 2026-10-26

## Context

C3 says actions are logged. A log the application can rewrite proves little. The service runs as a database role, so what that role may do is what an attacker who owns the application may do.

## Decision

`audit_log` is a table the application role may only `SELECT` and `INSERT` into. A trigger also refuses `UPDATE` and `TRUNCATE` for every role, including the superuser, and refuses `DELETE` of any row younger than the retention period (`audit_retention.days`, 365, never below 90). A separate `audit_retention` role holds `DELETE` and runs the retention query.
```

A decision record: a title, a status line, then the context, the decision and the consequences, so a reader finds the reasoning
in a fixed place.

## Mistakes people make

- **Editing generated files by hand** (`evidence/INDEX.md`, `build/report.md`). The next run overwrites them, and an edited
  evidence file fails the hash check.
- **Skipping the blank line** before a list or a table.
- **Pasting Python fragments** into Markdown code blocks where ruff 0.17 will try to format them; `tech/` is excluded in
  `pyproject.toml` for that reason.

## Check yourself

1. What marks a heading?
   **Answer:** One or more `#` at the start of a line.
2. Which evidence files are Markdown?
   **Answer:** `INDEX.md` and `C6-access-review.md`.
3. Why not edit `INDEX.md` by hand?
   **Answer:** It is generated and recorded in the manifest; a hand edit would fail verification.
4. How do you make a table?
   **Answer:** Rows of cells separated by `|`, with a separator row of dashes under the header.
5. Is Markdown executed?
   **Answer:** No; a viewer converts it to HTML.
